# 酒馆预设智能更新器 v1.1.0

支持从 Git 仓库 URL 安装的酒馆扩展，也保留酒馆助手 JSON 脚本版。适用于原生 SillyTavern 和 TauriTavern 的原始 Chat Completion 预设。

把作者新版预设合并到你正在使用的缝合版，并按现有名称保存。作者旧版作为共同基准，区分作者更新和你自己的条目。

## v1.1.0：从仓库 URL 安装

仓库根目录包含 `manifest.json` 和已经构建好的 `index.js`，安装时不需要运行 npm，也不需要导入 JSON。扩展版使用酒馆原生入口和用户设置，**不依赖酒馆助手**。

**安装前提：仓库必须可以匿名读取。** TT 当前安装器只支持匿名 HTTP(S) Git 仓库，不支持私有仓库认证、带用户名或令牌的 URL、SSH 或 credential helper。GitHub 网页上的登录状态不等于酒馆的 Git 读取权限。仓库设为私有时，下方普通 URL 尚不能用于 TT 安装；需要先由仓库所有者决定是否公开。

1. 确认仓库可以匿名读取后，打开酒馆的 **扩展 → 安装扩展**。
2. 粘贴仓库根地址，使用默认 `main` 分支：

   ```text
   https://github.com/ines02190621-dotcom/tavern-preset-updater
   ```

3. 安装完成后刷新酒馆。
4. 在 **扩展面板 → 酒馆预设智能更新器 → 打开预设更新器** 中使用。
5. 更新本工具时，在酒馆的扩展管理中检查并更新，然后刷新。没有开启无提示自动更新。

**扩展更新与作者预设更新是两回事。** 扩展面板的更新只更新本工具的代码；作者发新版预设后，仍在更新器中选择作者 JSON，核对三方预览，再确认备份并原位更新。

### 从旧 JSON 脚本版升级

- 先从旧版导出一个完整恢复包，关闭旧的“预设更新器”全局脚本，再安装扩展并刷新。
- 在同一浏览器、同一酒馆地址、同一用户下，扩展会读取旧版保存的全局数据空间编号，沿用原有 IndexedDB 绑定和备份；不会重建或覆盖原备份。
- 扩展版与 v1.1.0 JSON 版共用数据空间。检测到两个不同编号时停止写入，提示核对恢复包，避免切到一份空备份库后误操作。
- 换地址、换设备或清除应用数据后，浏览器备份不会自动跟随；请使用完整恢复包。
- 未完成的文件选择和对应关系不跨刷新保留，需要重新选择。

### 继续使用 JSON 脚本版

`dist/酒馆预设智能更新器-v1.1.0.json` 仍可导入酒馆助手的全局脚本库。推荐在扩展版和脚本版中选择一个入口；同版本同时加载时，扩展入口优先，共用一个窗口和数据库。

## v1.0.3 新增：折叠分组（大条码）合并

以后更新时，不只合并条目和顺序，也处理柏宝箱保存的“每条属于哪个折叠组”的记录。原来普通扩展默认保留整项旧值，会使作者新增条目缺少组内归属；本版将已识别的分组记录单独合并，并同步转换条目编号。

- 作者新版明确写了分组：新增条目加入对应组；已有条目按三方差异处理分组变化。
- 你自己缝入的条目：保留当前分组、组内附加设置；原本在组外的继续独立保留。你手动拖回去的已有条目，在之后更新时会作为当前设置参与比较。
- 已有分组的总开关和折叠状态继续用你的；“让作者更新现有条目的默认开关”只涉及条目开关，不覆盖分组总开关。
- 两边都改变同一条目的分组，或分组对应不明确：预览中必须选择。作者删除你只调整过分组的条目，也需要确认删除。
- 作者新版没带分组记录：保留已有条目的归属；对已经放进列表的新增条目，让你明确选择分组或保持独立，选择完成后才能更新。
- 新增 **查看合并后的折叠分组（大条码）**：直接列出每组名称、成员、总开关，以及分组外的独立条目。
- 改变格式或恢复选择后，会重新显示由该选择产生的后续问题，避免尚有必选项却找不到选择框。

**升级：**关闭旧脚本，导入 `酒馆预设智能更新器-v1.0.3.json` 并覆盖，刷新酒馆后启用。已保存的绑定和备份沿用，无需重新首次绑定。本版面向今后的合并，不会在导入时擅自调整当前预设；本次已经散出的条目可按你原来的习惯手动拖回。

**已识别格式：**`extensions.baibaiToolkit.presetPromptGroups`，以及柏宝箱兼容导入的 `extensions.entryGrouping`（成员列表、起止范围；数组或 groups / entries / entryGroups / items 包装）。本版以明确成员列表同步兼容记录，防止范围边界把无关自定义条目一起划入。分组对应优先使用稳定编号，再核对唯一名称或唯一作者成员集合；重名或拆分有歧义时不会自动猜。

这不等于支持所有分组插件。Luker、ST-PromptFolding 等其他分组格式不会自动改写其内部数据，检测到时提示单独核对。柏宝箱自身的刷新使用原生预设重新应用流程；旧插件版本的显示仍需以本机结果为准。

## v1.0.2 新增：对应关系关键词搜索

核对对应关系时，可以按条目名称直接搜索，例如输入“三水”，筛出“三水草稿cot”“三水续写”等名称含“三水”的条目。

- 每个对应框上方的搜索框：筛选该框中的候选条目。确认新版对应时，搜索的是作者新版；首次绑定时，搜索的是当前缝合版。
- 每组对应关系上方的“查找要核对的旧版条目”：搜索上面显示的旧版条目，已折叠的匹配条目也能搜到。
- 按名称包含关键词匹配，忽略大小写，支持中文；清空输入即可恢复完整候选列表。
- 搜索只改变显示范围。当前已选的对应项会保留，即使它不符合关键词，也会以“当前已选”显示；零匹配不会自动把条目改成删除。
- “不存在／已删除”选项始终保留，只有明确选择才变更对应关系。

关键词搜索功能继续保留；尚未保存的新版文件选择及对应关系，在升级后需要重新选择。

## v1.0.1 修复：点击按钮没有反应

第一版把隔离样式的 Shadow DOM 直接挂在 `<dialog>` 上，但浏览器标准不允许该元素作为 Shadow Host，真实浏览器会在窗口显示前抛出 `NotSupportedError`。此前的 DOM 测试替身没有实现这项限制，导致测试遗漏。

本版把 Shadow DOM 挂在弹窗内合法的 `<div>` 上。按钮在脚本载入时立即注册；点击后先显示窗口和初始化提示，再读取模块与数据库。模块或数据库初始化超时会显示原因并停止原位写入；创建窗口失败也会显示错误，并允许再次点击重试。已补充符合这条浏览器标准的回归检查。

这项弹窗修复继续包含在 v1.1.0 中，绑定和备份沿用原有数据空间，无需清除应用数据。

标准依据：[WHATWG DOM：合法的 Shadow Host 及 attachShadow 的异常规则](https://dom.spec.whatwg.org/#concept-attach-a-shadow-root)。

## 导入和第一次绑定

1. 扩展版按上方 URL 安装步骤打开；脚本版下载 `酒馆预设智能更新器-v1.1.0.json`。
2. 使用脚本版时，在酒馆助手的**脚本库 → 全局脚本**中导入并启用。使用扩展版时，在酒馆扩展面板点击“打开预设更新器”。
3. 点击脚本按钮 **预设更新器**。
4. 确认顶部显示的是正在使用的缝合预设。条目编辑弹窗里尚未保存的文字，请先保存。
5. 到 **首次绑定**，选择你当时用来缝合的**作者旧版原文件**。
6. 核对对应关系，确认多出来的是你自己的条目，勾选来源确认并保存绑定。

首次绑定记录来源并建立备份，不改动预设正文。没有当时的作者旧版时，不宜直接把最新版当作旧版绑定，否则作者已经新增或删除的条目可能被错误分类。

## 以后更新

1. 选中原来那个预设，打开更新器。
2. 在 **更新预设** 选择作者新版 JSON。
3. 核对条目对应关系，可输入关键词筛选旧条目和新版候选，再生成三方预览。
4. 展开作者新增、修改、删除和“我的条目”检查；双方改了同一字段时，下拉选择保留哪边。
5. 可查看合并后的折叠分组、顺序与开关。勾选已核对，再点击 **备份并原位更新**。
6. 在最后的目标确认中确认更新。成功后以作者新版作为下一次的基准。

脚本把目标名称固定为当前已存在的预设名称，不采用新版文件名创建预设。默认不会切换你的模型、地址或连接设置。

## 合并规则

| 情况 | 本版处理 |
| --- | --- |
| 作者旧版没有、你当前版本有的条目 | 视为自定义条目，正文和所有原始字段完整保留 |
| 自定义条目未放进顺序列表 | 继续保留为未使用条目，不擅自启用 |
| 自定义条目的开关及额外列表设置 | 按每个顺序组原样保留 |
| 自定义条目的位置 | 优先跟在原来的前一条保留下来的作者条目后面；没有前锚点时参考后锚点；保证自定义条目彼此的相对顺序 |
| 作者调整顺序导致锚点互相交叉 | 保留作者顺序和自定义条目的相对顺序；插入位置尽量还原，并提示检查 |
| 作者更新正文，你没有修改该字段 | 自动采用作者新版 |
| 作者和你分别修改不同字段 | 按字段合并 |
| 双方修改同一字段且值不同 | 必须选择；未处理完不能写入或导出正式结果 |
| 作者删除你没有修改的条目 | 在预览中列出，并纳入确认后的删除 |
| 作者删除你调整过的条目、开关或分组归属 | 必须选择保留或删除；选择保留时连同原列表设置保留 |
| 你删除的条目，作者未修改 | 保持你的删除 |
| 你删除的条目，作者又修改正文等字段 | 选择保持删除或恢复作者新版 |
| 现有条目的开关 | 默认保留当前值；可勾选跟随作者默认开关，再按三方规则处理 |
| 作者新增条目的开关 | 使用作者新版设置 |
| 采样等普通参数 | 三方比较；无冲突自动合并 |
| 模型、地址、代理、连接相关配置 | 保留当前配置 |
| 已识别的折叠分组 | 单独三方合并，保留自定义条目归属、现有分组总开关与折叠状态 |
| 正则、酒馆助手脚本和其他扩展 | 分别列出；默认保留当前整项扩展。明确选择采用作者扩展时才替换该整项 |

扩展项的替换范围与预设条目不同。例如选择替换整个 `tavern_helper` 项，会同时影响其脚本、变量以及你自己添加的扩展内容。已识别的折叠分组不在整项替换范围；同一 baibaiToolkit 项里的其他字段仍按整项选项处理。本版没有替扩展内部的脚本或正则进行逐项三方合并；使用默认“保留当前扩展”能避免这一类覆盖。

## 编号、重名和手动对应

- 优先使用原始 `identifier`，不能只凭名称判断归属。
- 编号改变时，仅当名称、正文、角色和条目类型完全一致，且两侧候选唯一，才自动建立对应。
- 仅同名但内容不同的候选需要手动确认；重名不会自动选一条。
- 可展开“核对其他已匹配条目”修改自动对应结果。
- 你明确选“不存在／已删除”后，另一侧剩余条目按独立新增或自定义处理。
- 作者新增编号与现有条目相撞时，需要选择跳过作者新增，或两条都保留。后者会为作者新增条目生成新编号；扩展若引用编号，需另行核对。
- 对应条目不足旧版的 40% 时，额外提示检查文件来源和大幅改版。
- 同一文件内的重复编号、重复引用、悬空引用或错误格式会阻止合并，避免猜测和误删。

作者重新编号后的对应关系会记住，并继续保留你本地条目的编号。后续版本仍可自动对比。

## 备份和恢复

**备份恢复**页提供：

- 恢复这一版：恢复更新前的完整预设、顺序、开关与作者基准。
- 导出完整恢复包：包含恢复所需预设和基准，可在同名预设中使用“从文件打开完整恢复包”。
- 导出备份预设：只导出原始预设，可通过酒馆自己的预设导入功能使用。
- 核对保存结果：当保存超时或中断时，检查后端文件究竟停在哪一步。

恢复也会先备份现状，所以恢复之后可以再回到修订后的版本，无需重新调用模型。预览、更新和恢复均不调用模型 API。

自动备份使用当前酒馆本地的 IndexedDB；用户空间由扩展用户设置中的编号区分，并兼容读取旧版酒馆助手全局变量。不会把完整备份塞进预设，也不会自动删除旧备份。空间不足或数据库不可用时停止原位写入。**清除应用数据、换设备或换地址前，先导出完整恢复包。**

如果恢复包来自“首次绑定”之前，其基准为空；恢复后需要重新首次绑定。这与恢复到当时的真实状态一致。

## 实际接口与兼容边界

核对日期：2026-11-16。查看了原生 ST、TT 以及酒馆助手的实际源码，而非按名称猜测接口。

| 接口或数据 | 原生 SillyTavern | TauriTavern | 本脚本用途 |
| --- | --- | --- | --- |
| `SillyTavern.getContext().getPresetManager('openai')` | 提供前端管理器 | 保留同一管理器入口 | 读取当前名称和原始预设缓存 |
| `getPresetList()` | 提供原始预设与名称索引 | 同样提供 | 保留未识别字段，不经助手简化模型转换 |
| `getChatCompletionPreset()` | `scripts/openai.js` 导出 | 同一路径导出 | 捕获当前界面已提交、可能尚未另存的设置 |
| `getPresetApplicationPromise()` | 等待异步应用 | 同样提供 | 避免预设尚未应用完就读取或刷新 |
| `savePreset(name, raw, {skipUpdate:true})` | POST `/api/presets/save` | 由父窗口 fetch 桥转给 Rust | 按现有名称保存，不走“导入为新文件”流程 |
| `/api/settings/get` | 返回磁盘预设及文件名列表 | 提供兼容路由 | 写入前检查外部改动，写入后核对完整结果 |
| `updateList(name, raw)` | 替换已有名称并触发应用 | 同样保留 | 核验保存成功后刷新正在使用的预设 |
| 酒馆助手脚本 JSON | `type:script`、`content`、`button` 等 | 通过相同的前端脚本运行层 | 可导入的全局脚本与按钮 |

酒馆助手也有 `getPreset`、`replacePreset` 和 `importRawPreset`。但其 `Preset` 是转换后的数据结构，会重建提示词字段和默认值，不能承担原始未知字段全部无损往返的承诺。因此本脚本不直接把作者原始 JSON 交给 `replacePreset`，也不走按作者新文件名导入的路径。

TT 后端并非 ST 的 Node 后端。本脚本调用两边共有的前端管理器与父窗口 fetch；本地模块也在父窗口加载，以复用酒馆真正的模块实例，避免在助手 iframe 内另建一套状态。

**支持范围：**原始 Chat Completion 预设，即含 `prompts` 和 `prompt_order` 的文件。Text Completion、世界书、角色卡不在这一版范围。扩展版无需酒馆助手；JSON 版需要酒馆助手脚本库。如果缺少上述接口、本地模块导入受限、当前不是聊天补全，或数据库不可用，会停用原位写入，提供离线文件对比与导出。

未指定“所有历史版本均兼容”的最低版本号。历史发行版本之间的导出和脚本接口可能有差别，运行时检测实际接口是准入条件。

**并发限制：**更新器自身的多个窗口使用同一用户空间的数据库互斥锁。每次保存前检查名称、当前设置、预设列表、绑定和磁盘内容。但原生保存接口没有原子版本号比较，也没有跨后端和 IndexedDB 的事务；无法绝对排除外部编辑恰好发生在最后一次检查与保存之间。保存时请避免其他设备、原生编辑器或同步程序同时修改同一预设。中断时保留写前日志，不自动重试覆盖或盲目回滚。

**名称限制：**绑定以酒馆现有预设名称为键。手动改名后需要重新绑定；恢复时也需要先选择备份记录中的同名预设，脚本不会为恢复另建一个新预设。

**离线导出：**导出只生成文件，不自动推进原位更新的作者基准。若之后用酒馆自己的导入功能采用该文件，应重新以作者新版绑定，避免基准落后。

## 验证结果

- 101 项自动化测试全部通过。包括原有 84 项，以及扩展清单、独立入口、延迟面板、旧数据空间沿用、同版本入口共存、设置保存失败和切换用户后的写入拦截等新增检查。扩展版和 JSON 版均跑通绑定 → 三方预览 → 保存 → 恢复 → 撤回恢复。
- 包括 200 组随机作者新增、删除和重排场景，以及 80 组随机分组移动、删除和新增场景；逐项检查自定义正文、全部字段、开关、顺序及分组归属。
- 使用 ST、TT 官方默认预设完成无改动往返比较。
- 覆盖同字段冲突、编号变化、编号碰撞、连续多版更新、本地删除、多个顺序组及空值语义。
- 覆盖备份失败、写入失败、后端返回不一致、绑定存储失败，以及并发编辑拦截。
- 在隔离 DOM 宿主与 IndexedDB 实现中，跑通首次绑定 → 预览 → 原位写入 → 恢复 → 撤回恢复；同时检查导入文本不会被当成 HTML 执行。
- 用已核对版本的柏宝箱原始读取与归一化函数验证产物：原生记录和兼容成员列表能读回一致的成员归属。
- JSON 解析、脚本语法检查通过。文件中的换行在解码后是真正换行。

## 开发复现

源码包包含本项目的实现、测试、锁定依赖与官方默认预设测试夹具。无需任何模型 API 密钥。

```sh
npm ci
npm test
```

构建产物为根目录 `manifest.json`、`index.js` 和 `dist/酒馆预设智能更新器-v1.1.0.json`。仓库已经提交构建产物，普通使用者安装时无需 npm。`npm test` 会先重新构建，再跑核心、保存适配、数据库和 DOM 流程测试。

可选真实浏览器测试需自行安装 Playwright 和 Chromium，然后执行 `npm run test:browser`。可通过 `CHROMIUM_PATH` 指定现有 Chromium。此流程使用本地隔离宿主，不连接真实用户数据。

本项目自身代码采用 MIT 许可。官方默认预设夹具及其许可证另放在源码包的 `research` 目录，来源见上方链接。
